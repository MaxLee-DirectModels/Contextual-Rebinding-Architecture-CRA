# Contextual Rebinding Architecture

**Local law. Typed passage. Destination Standing.**

Contextual Rebinding Architecture (CRA) is an executable research architecture for determining what survives when claims, evidence, obligations, authority, identity, state, or effects cross between changed contexts or autonomous regimes—and what must be earned again locally.

> A result belongs to the Regime, Demand, and Basis that earned it. Elsewhere, only typed material may pass; Standing must be earned again.

Public release: **CRA v1.1** — 8 August 2026  
Release status: **First public release**

This repository contains the complete public CRA architecture: the compact human-readable document, executable finite-reference packet, hostile qualification suite, cryptographic manifest, and optional Structural Lexicon.

## Why CRA exists

Matching words, values, or bytes do not guarantee matching meaning. Source approval does not create destination permission. Evidence does not automatically become Judgment; Judgment does not automatically become Standing; Standing does not automatically become Effect.

CRA makes those boundaries executable. It identifies the proof obligations created by a change of context, accounts for what passes and what changes, and returns only the result earned under the destination's own rules.

## Core structure

CRA keeps a seven-root federation kernel:

| Root | Job |
| --- | --- |
| **Regime** | Declares one versioned local vocabulary, type system, rules, verifiers, authority roots, and capabilities. |
| **Demand** | States the exact requested Return, intended use, protected conditions, horizon, and required Standing. |
| **Basis** | Freezes the complete fingerprinted dependency closure for one Demand and operator. |
| **Judgment** | Records one destination-local conclusion verified under the current Basis. |
| **Correspondence** | Defines a typed, partial, directional, bounded relationship between Regimes. |
| **Crossing** | Records one actual application of a Correspondence and accounts for every source and destination occurrence. |
| **Standing** | Records destination-local permission to use one Judgment for one bounded purpose. |

Six executable operators act on that structure:

`Contextualize` · `Judge` · `Apply` · `Admit` · `Compose` · `Reassess`

## Exact outcomes

Every operation returns exactly one outcome:

- **EARNED** — every mandatory proof obligation has a verified witness.
- **REJECTED** — a verified counter-witness establishes that a mandatory condition fails.
- **OPEN** — neither completion nor verified failure is earned.

`OPEN` is a substantive result, not a generic error or unexplained null. CRA returns a typed `OpenCertificate` containing the first detected break, deepest independently verified weaker result or `NONE_EARNED`, disclosed remaining obligations, localized affected Return components, reverse evidence, Standing ceiling, and earliest lawful reentry point. It infers no Standing or Effect.

The certificate is fail-fast: it identifies the earliest detected break without pretending that every later or open-world blocker has already been discovered.

## What CRA can be used for

- Translation and semantic-transfer audits
- Projection, abstraction, and bounded compression
- Schema, model, and version migration
- Institutional admission and authority-sensitive reuse
- Provenance and dependency reconstruction
- Obligation transfer and consequence accounting
- Succession between releases or systems
- Cross-model and cross-regime interoperability analysis

CRA is a kernel for these jobs, not a substitute for the destination's domain theory, truth source, legal authority, security system, or transaction engine.

## Quick start

Extract the AI packet, enter its `CRA-v1.1` directory, and run:

```bash
python scripts/cra.py verify --root .
python scripts/cra.py inspect --root .
python scripts/cra.py inspect --operation rebind --root .
python scripts/cra.py qualify --root .
```

To query the Structural Lexicon:

```bash
python scripts/cra.py lexicon --term standing --root .
python scripts/cra.py lexicon --category open-frontiers --root .
```

`run` accepts complete typed candidate records, not raw prose. Begin with `starter.input` from `inspect --operation OPERATOR`.

## Executed and unexecuted boundaries

The reference profile executes finite local formation, unary translation, exact projection, bounded cardinality-reducing compression, exact two-hop semantic composition, and relation-specific `COPY_LICENSED`, `SPLIT`, and `MERGE` accounting.

Fan-in, fan-out, two independently executed diamond paths, cycles, and nested passage remain specified but not finitely executed. Observation is qualified only for stage separation and trace consistency. Transactions and world actions require external profiles capable of earning their own durability, atomicity, recovery, occurrence, attribution, and effect claims.

## Six open research frontiers

1. Independent reconstruction
2. Comparative external value
3. Durable recovery
4. Adversarial authenticity
5. Demand and dependency discovery
6. Adapters and broad interoperability

Each frontier has an explicit identity, closure condition, evidence requirement, and lawful reentry route.
